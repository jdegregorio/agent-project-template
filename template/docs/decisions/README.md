# Architecture decisions

Use this directory for durable technical choices whose rationale future maintainers will need. Specifications own observable behavior; decision records own the reasoning behind implementation and architecture choices.

Name records `NNNN-short-title.md`, starting with `0001`.

Each record should contain:

- Status: proposed, accepted, superseded, or deprecated
- Context: the constraints and forces behind the decision
- Decision: the chosen approach
- Alternatives: meaningful options considered
- Consequences: benefits, costs, risks, and follow-up work
- References: related specifications, changes, incidents, or pull requests

Do not rewrite accepted history to make it look inevitable. Supersede an old record with a new one and link both directions.
